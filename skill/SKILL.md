# Jacky-yazai：芽仔手绘解说成片

工程目录（下文命令都在这里执行）：

    <repository-root>

- 分镜字段、每个模板怎么写：[references/storyboard.md](references/storyboard.md)
- 离线运行示例：先执行 `python3 scripts/demo_setup.py`，再按 README 预览和渲染。该示例使用演示时间，不是真实配音对齐。

本 skill 同时用于 Claude Code 和 Codex。Codex 的特殊要求见文末「在 Codex 里运行」。

**分工**：你只写 `storyboard.json`，内容包括选模板、填文字、写口播触发词（cue）、写芽仔表情。坐标、出现时刻、动效、音量都由工程决定。不要为了单条视频改引擎代码；模板不够用时告诉用户，不要临时硬改。

## 流程

1. **审稿、定画幅**
   - 读口播稿，确认四件事：
     - 画幅：**3:4**（口播、快节奏，默认）还是 **16:9**（教程演示）；
     - 有没有截图或录屏素材；
     - 有没有自配的配乐；
     - 要不要叠加读稿小窗。
   - 口播稿逐字保留，配音照它念，只切行：一行就是一条字幕，8–20 字，在逗号、句号处切，每行配一句英文 `en`。
   - 稿子里出现外平台名称（微信、抖音、携程、网址等）时，先提醒用户，容易被限流。
2. **建项目**
   - 分镜文件：`projects/<英文短名>/storyboard.json`，先写 `title`、`voice`、`lines`。
   - 素材放 `projects/<名>/assets/`：截图命名 `01.png`、`02.png`…；配乐放 `music.mp3`。
3. **截图打码**（有截图就必做）
   - 运行 `python3 scripts/mask_deck.py projects/<名>/assets/<截图目录>`。
   - 片子里用 `<截图目录>/sm/NN.jpg`。
   - 读 `mask-report.md`，告诉用户打了哪些码。
4. **配音**
   - 运行 `pnpm voice <名>`，输出 `voice/words.json`（逐字时间）。
   - 有缓存：只有改了 `lines` 才会重新合成，重新合成会产生费用。
   - 缺凭证时让用户配置 `.env.local` 里的 `VOLC_TTS_*`。不要读出或打印密钥内容。
5. **写分镜**：填 `scenes`，规则见下文，字段见参考文件。
6. **验收**
   - 运行 `pnpm qa --p <名> --fmt 3x4`，必须全部 ✓。不通过就按提示改分镜，不改引擎。
     - qa 会在每个画面事件的起点、强调峰值和回落时刻检查芽仔遮挡、同场文字互挡与出界、竖屏安全区，并确认每场无动画时正文像素静止。报告在 `out/qa/overlap-3x4.md` 和 `qa-3x4.json`。
     - 预览不想画口播小窗占位时加 `--query pip=none`。
   - 抽帧看关键时刻：`pnpm render --p <名> --fmt 3x4 --stills 1.2,30.5,…`，看每场第一帧和每个表情出现后 0.5 秒。图在 `out/stills/`，用你的看图工具逐张打开检查。
   - 也可以实时预览：运行 `pnpm dev`，打开 `http://localhost:5188/?p=<名>&fmt=3x4`。
7. **出片**
   - 竖屏：`pnpm render --p <名> --fmt 3x4`；横屏：`pnpm render --p <名>`。
   - 有读稿录像时加 `--pip <读稿.mp4>`（只对竖屏生效）。
   - 2 分钟的片子，每个画幅大约 3–5 分钟出完。
8. **交付**
   - 给出 `out/demo-3x4.mp4` 或 `out/demo.mp4` 的路径，以及 qa 的结论和表情时间表。
   - `out/av-sync.md` 里的"可放成品展示的留白"一并告诉用户。
   - 问用户哪一秒不对。

## 分镜规则

- 一场只讲一件事。场景从 `line`（行号，从 0 起）开始，到下一场开始为止。
- 第一场用 `headline`，做结果式大标题，开场就出，不堆截图；最后一场用 `ending`。
- cue 只在本场口播范围内查找，越过下一场会报错。
- **画面和口播同时出现**：每个元素都写 `cue`，即口播里触发它的原词。
  - 从稿子里逐字摘 2–6 个字；数字按口播的写法写（"六万"不写成"6万"）。
  - 同一场里的 cue 按口播先后顺序写。
- 截图只在"说到它"的那一刻出现，一场最多 2 张（展示页 4 或 6 张）。
- 文字要短：标签不超过 10 字，卡片标题不超过 8 字，竖屏大标题一行不超过 8 字。
- **画面默认静止，不抖动**。普通文字和卡片约 0.15 秒淡入后就不动；`boil` 已停用。
  - 抓眼球靠单次强调：在元素的 `{text, cue}` 里加 `"em": true`，只放大这个元素里最大的那行字到约 1.10 倍，0.6 秒内归位；
  - 数字、大标题、结论都**不自动**强调，需要时自己写 `em`；
  - 每场最多 1 个，多写会报错。放不下时引擎自动降倍率或改成一次黄色底色高亮，写 `"peak": 1` 可直接选高亮。

### 选模板

按内容结构选择，以下模板在 3:4 和 16:9 均可用。

| 内容结构 | 用哪个模板 |
|---|---|
| 开场结果、钩子 | `headline` |
| 一句核心观点、原话 | `quote` |
| 做事顺序、方法步骤 | `flow` |
| 因果推进、业务闭环 | `diagram`（`chain` / `loop`） |
| 阶段总览 | `road` |
| 逐步展开讲 | `chapter` |
| A 和 B 对照、以前和现在 | `versus` / `compare` |
| 比例分配（2–3 段） | `split` |
| 两段真实占比对比 | `allocation` |
| 大数字 | `stats` |
| 三方协作（图标） | `triad` |
| 目标冲突、角色协作、收束到共同结果 | `roles` |
| 纠正旧认知 | `verdict` |
| 全片最强调的一句 | `burst`（整片建议最多 1–2 次） |
| 列举 3–4 个要点 | `prompt` |
| 成品截图 | `showcase` |

- 不要为了凑模板种类制造原文没有的关系；气泡（`prompt`）用于真正的表达或少量并列要点，划线（`verdict`）只用于原文明确否定的旧观点。
- 同一模板不超过全片场景的 35%；不要连续 3 场用同一模板。QA 会提示，不会因此判失败。
- `diagram`、`roles`、`allocation` 按 3:4 排版，16:9 下整体居中平移；长标签会报错，缩短显示文字，保留原字幕。
- `flow.steps[].icon`、`versus` 和 `triad` 使用 Tabler outline 英文图标名，分镜构建前自动预加载；名称错误直接报错。

## 芽仔规则（只有这几条）

1. **位置不用写，由场景自动决定**：
   - 开场大标题、主角页、结尾：大芽仔；
   - 纯文字的场景：在右下角放大，旁边是文字；
   - 有截图演示的场景：缩在右下角，完全静止，面罩纯黑。
2. **表情只放在口播里有情绪的词上**：写 `"yazai": {"face": "…", "faceCue": "原词"}`。
   - 只能用 5 种：`surprise` 惊讶、`happy` 开心、`doubt` 疑惑、`idea` 灵感、`loading` 加载中。
   - 表情只亮面罩：不出头顶符号、不自动放大、不推镜头。芽仔平时完全静止。
   - 想让芽仔配合内容动一下，加 `"action"`（由 `faceCue` 触发，只做一次）：`retreat` 收身后退、`approach` 走上前（必须同时写 `"at": "front", "walk": true, "cue": "原词"`）、`celebrate` 小幅跃起、`observe` 注视重点、`push` 前倾。一个表情只配一个动作。
   - 流程链（`flow`）里芽仔自动站到节点上，随步骤一格一格往前跳，不用写。
   - 路线图（`road`）里芽仔沿曲线走到各站，沿路走动不占普通走动次数；换场自动回默认站位。
   - 对照（`versus`）某侧写 `yazai: true`，芽仔就替代该侧图标参与画面，最多一侧使用。
   - `quote` 逐字出现时自动显示 loading 说话点阵，不显示头顶符号、不推近，也不计入表情次数；正式表情优先。
3. **频率**：整片不超过 6 次，两次至少隔 10 秒，大约 20 秒一次为宜。拿不准就不加。
4. **走动**：只在剧情转折处用，例如"从出主意到直接干活"的结论页。写法是 `"at": "front", "walk": true, "cue": "原词"`，整片不超过 2 次，建议只用 1 次。
5. **结尾**：面罩会自动亮起"Jacky / 无限生长"像素字，不用写。
6. **不要做**：跟着每个卡点换表情、跟着每个元素走位、歪头卖萌、每个表情都配动作。
7. 上面这些次数和间隔 `pnpm qa` 都会检查，超了就不通过。

## 版式与平台安全区（引擎已处理，写分镜时别把字塞太长）

- **3:4**
  - 演示区在中上部（y<800），左右对称；
  - 左下角是读稿小窗，右下角是芽仔，字幕在底部居中。
  - 抖音右侧按钮栏大约在 x>930、y>800 的区域，qa 会检查有没有内容进去。
- **16:9**：内容区在 x≤1680，右下角留给芽仔，字幕在底部居中。

## 声音

- 人声峰值 −1 dBFS，音效 −12 dBFS。
- 配乐用 `assets/music.mp3`，按用户调好的音量铺底（约 −18 dBFS），自动循环、淡入淡出；没有就用程序生成的轻配乐。
- 不用有版权的音乐。

## 常见报错

- **"口播里找不到关键词「X」"**：这个 cue 不在该场及之后的口播里，或者顺序写反了。改成稿子里的原文，并调整顺序。
- **"cue「X」越过本场景口播范围"**：这个词在下一场才说到。换成本场里的原词，或调整场景的 `line`。
- **"每场只能指定一个 em 重点"**：删掉多余的 `em`。
- **"标签「X」过长"**：缩短显示文字（字幕原文不用改）。
- **qa 报遮挡或安全区**：删减这一场的元素、缩短文字，或者这一场不加表情。
- **qa 报抢戏**：删掉最不关键的表情，或者拉开表情间隔。
- **表情早于换位**：`yazai.cue` 要不晚于 `faceCue`。

## 在 Codex 里运行

- 从工程目录启动 Codex，或者每条命令都先 `cd` 到工程目录。
- **要申请在沙箱外运行的命令**：
  - `pnpm render`、`pnpm qa`、`pnpm dev`：都会启动本机 Chrome，而 Codex 的 macOS 沙箱会让 Chrome 一启动就崩溃（报错里有 `SIGABRT` / `kill EPERM`）。
  - `python3 scripts/mask_deck.py`：用到 macOS 文字识别，实测在沙箱里卡住不返回。如果打码报"一行字都没识别到"，也按这条处理，绝不能跳过打码。
  - 执行时直接申请提权（escalated），并说明原因（"需要启动本机 Chrome 逐帧截图"或"需要 macOS 文字识别给截图打码"）。
  - 用户可以选择"以后同前缀不再询问"，批准一次即可。
  - 出现上述报错时不要改代码，也不要换浏览器绕过，直接按这条申请提权重跑。
- **沙箱内能正常运行的**：读写工程文件、`pnpm typecheck`、看图。`pnpm voice` 需要联网访问火山接口；当前配置下网络可用，如果被拦截，同样申请提权。
- 已有环境不要重装或删除 `node_modules`；若尚未安装依赖，按 README 的新克隆步骤安装。工程已关闭 pnpm 运行前的依赖自动检查（`verifyDepsBeforeRun: false`），因为在 Codex 里这个检查会误判，并尝试清空 `node_modules`。
