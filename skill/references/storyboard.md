# storyboard.json 字段

位置：`projects/<名>/storyboard.json`。字段说明见下文。公开离线演示通过 `scripts/demo_setup.py` 生成，不包含私人内容项目。

## 顶层

```json
{
  "title": "片名（只做记录）",
  "voice": { "start": 0.8, "gap": 0.28, "tail": 2.2 },
  "lines": [{ "zh": "我真的被干懵了，", "en": "I'm honestly stunned —" }],
  "scenes": []
}
```

- `voice.start`：第一句开口的时刻（秒）。
- `voice.gap`：句与句之间的停顿（秒）。
- `voice.tail`：最后一句说完后画面再留多久（秒）。
- `lines`：一行就是一条双语字幕。配音把所有 `zh` 连起来念，遇到 。！？ 切句。`en` 必填。改 `lines` 后要重新运行 `pnpm voice <名>`。

## 场景通用字段

- `line`：这一场从第几行开始（从 0 起），到下一场的 `line` 为止。
- `template`：模板名，见下文。
- `yazai`：可选，芽仔表情和换位（见文末）。
- **带 cue 的元素**统一写成 `{ "text": "显示的字", "cue": "口播原词" }`。可以加 `"em": true` 或 `"peak": 1`，见文末「单次强调」。
- 顶层 `boil` 已停用：写 `"boil": true` 会报错。画面使用稳定字形，不做线条抖动。
- `line` 必须是有效且不重复的零基行号。

**cue 的匹配方式**：
- 只比对字母和数字，忽略标点、空格和大小写。
- 从这一场的第一行开始往后找，**只在本场口播范围内**找；越过下一场的 cue 会报错。
- 同一场里，按下面每个模板列出的**字段顺序**依次往后找，所以要按口播的先后顺序填。
- 以下几种不受顺序限制，都从本场第一行起找：标记为「任意顺序」的字段，以及 `yazai` 的 cue。
- 两个元素可以用同一个 cue，它们会同时出现。

## 模板

字段按 cue 查找的顺序列出。标「仅 16:9」的字段在 3:4 画幅下不显示。

### headline：开场结果式大标题

开场第一场用。标题不等口播，开场就逐行淡入。

- `lines`：`[{ "text", "size", "font"?: "en", "hl"?: "#ffd240" }]`。
  - `size` 按 16:9 写（例如 116–150），3:4 会自动缩到 0.78。
  - `hl` 是荧光笔底色。
  - 一般 2–3 行，每行不超过 8 字。
- `chip`：`{text, cue}`，任意顺序。
- `top`：仅 16:9，第一行标题的 y 坐标，默认 330。

### hero：主题词

一个英文或产品大词，下面配标签。

- `mark`：仅 16:9，`{text, cue}`，红色手写记号。
- `title`：`{text, cue}`。大字，建议用短英文；16:9 超宽时自动缩小字号。
- `chips`：`[{text, cue}]`，不超过 2 个。

### prompt：给 AI 的一句话、指令或要点

- `doc`：`{title, sub, cue}`，左侧（3:4 在顶部）的文档图标。
- `label`：`{text, cue}`，气泡框与标签同时出现，先按标签和首条要点的较早时刻减 0.1 秒计算，再限制框内空白最多 0.1 秒；因此有要点时跟首条要点走，没有要点时跟标签走。
- `bullets`：`[{text, cue}]`，编号要点，不超过 4 条，每条不超过 12 字。

### split：比例分配

- `title`：字符串，开场即在长条上方。
- `parts`：按 cue 顺序写 `[{pct, label, sub?, cue, em?}]`。两画幅均 2–3 段，pct 为正数且合计 100。
- 每段在 cue 时用排线从左向右涂满（0.35 秒），数字和说明同时出现。`em: true` 只强调该段数字。
- 与 allocation 的区别：split 支持 2–3 段、排线涂色；只有两段且要突出真实宽度对比时用 allocation。
- 3:4 条宽 900、高 120；16:9 宽 1400、高 140。label 建议 ≤5 字，sub ≤6 字；过小的段容不下百分比会报错。

### quote：金句气泡

- 外观：贴纸气泡（深色错位投影、尾巴与框一体指向芽仔），左上角黄色引号徽章，框高随行数收缩；每行打完扫一道荧光笔。
- `text`：金句；3:4 字号 70、16:9 字号 80，自动换行（优先在逗号、句号后断）且最多 3 行，超出报错。
- `cue`：从本场起按顺序查找；框提前 0.1 秒出现，文字从关键词开口到所在字幕行末按字数平均逐字显示。建议 cue 靠近句首，避免整句挤在很短的行尾。
- `by`：可选署名，文字完成后右下角显示“— 署名”。
- `em`：可选，强调文字；每场最多一个重点。
- 尾巴指向芽仔。自动 loading 说话点阵带 `talk: true`，QA 不计入正式表情次数；不显示头顶符号、不推近。

### burst：爆点徽章

- `text`、`cue`：按本场起点查找。不规则手绘星形贴纸（斜线填色、错位投影、略微倾斜）砸下，四周画出冲击线，同刻彩纸与芽仔跳跃。文字先缩小字号放进一行，放不下才换行。burst 是唯一保留砸下动效的模板，其他卡片与印章一律淡入。
- `sub`：可选字符串，徽章出现 0.4 秒后以小标签弹出。
- `em`：可选，徽章文字在砸下后再做一次单次强调。
- 两画幅均只容纳一句短语，text 建议 ≤4 字、sub ≤10 字；整片建议最多 1–2 次。

### flow：流程链（图标或数字节点）

- `title`：字符串，开场就在。
- `steps`：按 cue 顺序写 `[{text, cue, icon?, em?}]`，两画幅均 3–5 个节点；text 建议 ≤5 字。
- 3:4 为两行之字形（3 个节点时一行）；16:9 横排。箭头提前描线，当前节点高亮，经过的节点打勾。
- **芽仔参与**：本场芽仔离开右下角，站到当前节点上方，说到下一步就跳到下一格。节点同时出现时也会依次跳（每格 0.3–0.55 秒，按本场剩余时间压缩，跳不完的不跳）。这一场芽仔较小，不要在 flow 场景里写表情。
- 总览可让所有节点使用同一个概括词 cue（如“五步”），同时展开并保持各节点颜色；后续细讲另外使用 chapter，避免 cue 越过下一场。
- `icon` 可选 Tabler outline 英文名（如 `photo`、`magnet`、`target`），有值用手绘图标替代序号，无值仍显示序号；`em: true` 可强调单个节点。

### road：路线图，芽仔沿路走

- `title`：字符串，开场显示。
- `stops`：按 cue 顺序写 `[{text, cue, em?}]`，两画幅均 3–6 站，text 建议 ≤5 字。
- 站点按道路弧长近似等距排列；口播对应时刻弹出序号圆牌及文字。`em: true` 可强调单个圆牌。
- 芽仔比例 0.32，开场到道路起点，之后沿同一条三次贝塞尔曲线碎步走，不在两站间直线穿行。到最后一站后停住，换场自动回下一场站位。
- 所有 cue 必须在本场；少于每站 0.25 秒或站点超出本场会报错。总览可共用“五步”一类 cue：路标同时展开，芽仔以最多 0.65 秒一段依次走，后续 chapter 细讲。
- QA 只跳过带 `data-road` 的道路线遮挡，站牌、文字和安全区仍检查；road 走动不计入普通走动 ≤2 次。
- 3:4 道路从 (120,760) 到 (960,300)；16:9 从 (150,760) 到 (1600,380)，右侧为文字和角色留余量。

### versus：两方对照，芽仔可作演员

- `left`、`right`：`{icon?, title, yazai?, points?: [{text, cue, em?}]}`。
- 每侧需要 title，以及 icon 或 `yazai: true`。最多一侧用芽仔，比例 0.45；这一侧不画图标。没有芽仔的一侧 icon 必填。
- 标题和角色/图标开场出现；要点分别从本场起点查 cue（左右两侧任意顺序，不相互推进游标）。cue 越过下一场会报错。
- 两画幅每侧最多 2 个要点；3:4 每侧一行排 1–2 枚 chip，text 建议 ≤6 字；16:9 建议 ≤7 字。超宽会报错，请缩短。`em: true` 可强调一枚 chip。
- 3:4 上下对照，VS 放在两方之间偏左，为芽仔与上一场延续的表情留出空间；16:9 左右对照，VS 居中。
- 图标尺寸 3:4 为 140、16:9 为 180。

### triad：三方协作

- `nodes`：按 cue 顺序写 `[{icon, text, sub?, cue, em?}]`，两画幅都必须恰好 3 个节点。text 建议 ≤4 字，sub ≤4 字。
- 三个顶点依次出现手绘图标、名字和小字；两端节点都出现时连接双向箭头。
- `center`：共同目标字符串，最后一个节点出现后 0.3 秒淡入；建议 ≤10 字（3:4 最长框宽 740、16:9 为 930，超宽报错）。
- 顶层 `em: true` 强调中心框；`nodes[].em: true` 强调节点。每场最多一个重点。
- 与 roles 的区别：triad 固定三方并用 Tabler 图标、两两双向箭头；需要表达冲突、或 2 方 / 收束到共同结果时用 roles。

### 图标名与加载

- 图标使用固定依赖 `@tabler/icons@3.48.0` 的 outline 名称，例如 `crown`、`flag`、`tool`、`user`。
- 分镜加载后先递归收集并去重所有 `icon` 字段，再预加载，仅完成后才同步构建分镜；所有模板无需自行等待。diagram / roles 的 `icon` 是引擎自带图元，不参与 Tabler 预加载。
- 图标路径统一转为 rough.js 手绘线，不加载远程图标服务。不认识的名字会报“图标「name」不存在，到 https://tabler.io/icons 查英文名”。

### stats：大数字

- `cards`：`[{num, unit, label, cue, em?}]`。3:4 最多 2 张，16:9 最多 3 张。数字不再自动强调，需要时写 `em: true`。
- `stamp`：`{text, cue}`，印章，例如"交付!"。
- 3:4 可指定 `variant: "production"`：以素材图元和时钟表现产出与周期，配合两张 cards，不画大数字框。

### chapter：步骤章节

最常用的模板。带步骤编号，下列字段可以任意组合。

- `stop`：第几步，从 1 开始。步骤条的格数等于全片最大的 `stop`，几步就画几格。连续两场用同一个 `stop` 时，章节标题保留不重画，用来接着讲。
- `title`：章节标题，不超过 10 字。`sub`：小字说明。
- `pages`：`{count: "30 页", cue, shots: [3 张图]}`，一叠页面加 4 个勾。3:4 必须带 `shots`。
- `search`：`{query, cue}`，搜索框。
- `cards`：`[{title, sub, cue}]`。没有截图时竖排大卡，有截图时在截图下方横排小卡。
- `chips`：`[{text, cue}]`，标签，会自动换行。
- `issues`：`[{text, cue}]`，红色"⚠"问题标签。
- `stat`：`{num, unit, cue}`，数字贴纸。
- `stamp`：`{text, cue}`，印章。
- `shots`：`[{src, cue}]`，任意顺序，最多 2 张，第二张叠在第一张上。

有 `shots` 或 `pages` 的就是**演示场景**，芽仔自动缩在右下角。

### showcase：成品展示墙

- `shots`：`[{src, cue}]`，4 或 6 张，按顺序逐张弹出。
- `label`：`{text, cue}`，任意顺序，顶部标签。
- `mark`：仅 16:9，`{text, cue}`，任意顺序。

### compare：对比

- `left`：`{ title, steps: [{text, cue}] 不超过 4 个, result: {text, cue} }`。3:4 下 steps 超过 2 个会排成两行，整块自动上移。
- `right`：`{ title, result: {text, cue} }`。`right.result` 比左边结果晚 0.35 秒出现，可以和左边用同一个 cue。
- 两边的 `title` 开场就显示。

### verdict：结论（旧说法 → 新说法）

- `old`：`{text, cue, strike}`，灰字旧说法。`strike` 是触发红线划掉它的口播原词。
- `new`：`{text, cue}`，大字新说法，带荧光笔底色。
- `stamp`：`{text, cue}`，印章。
- `chip`：`{text, cue}`，底部互动标签，例如"评论区聊聊…"。

### ending：结尾

- `word`：像素字标，默认 `"JACKY"`。它在口播说到"Jacky"时落下，**所以结尾口播必须包含"Jacky"**。
- `tagline`：`{text, cue}`，标语。标语出现 0.9 秒后，芽仔面罩亮起"Jacky / 无限生长"。

## 截图 src

- 路径相对项目目录，例如 `"assets/deck/sm/06.jpg"`，必须用打码后的 `sm/` 版本。
- 按 16:9 比例裁切显示，截图最好是横版。

## diagram：因果链或闭环

- `variant`：`chain` 或 `loop`，必填。
- `title?`：`{text, cue}`，标题。
- `nodes`：2–4 个 `{text, cue, icon?, sub?, em?, peak?}`。
- 节点及连线在 cue 出现；loop 的返回箭头随最后节点出现。2 节点左右，3 节点递进，4 节点环绕或两行。cue 在本场任意顺序匹配。
- `icon`：引擎自带手绘图元，可选 `paper` 素材、`person` 人物、`clock` 周期、`target` 目标、`shield` 安心、`window` 窗口、`light` 光孔、`flywheel` 飞轮、`gift` 激励、`tool` 工具；默认 `paper`。
- 短标题通常 ≤6 字，说明 ≤8 字；实际字宽超出引擎空间时明确报错。
- 与 flow 的区别：flow 是做事步骤、芽仔在节点上跳；diagram 是因果或业务推进，能画闭环。

```json
{"line":0,"template":"diagram","variant":"chain","nodes":[
  {"text":"素材生产","cue":"素材生产","icon":"paper"},
  {"text":"获客跟上","cue":"获客","icon":"target","em":true}
]}
```

## roles：角色关系

- `title?`：`{text, cue}`。
- `relation`：`conflict` 或 `cooperate`。
- `roles`：2–3 个 `{text, cue, sub?, icon?, em?, peak?, now?}`。text 为角色或其核心诉求，sub 为短职责，默认人物图元。
- `result?`：`{text, cue, sub?, em?, peak?}`。出现时从各角色收束到共同结果；conflict 用红色。没有 result 的 conflict 会在角色之间画一道冲突线。
- `now: true` 仅用于上场角色在相邻场景继续显示；仍须写本场有效 cue，不适合提前披露新信息。
- 两角色标题建议 ≤8 字，三角色 ≤6 字；不写页面坐标。

## allocation：真实比例

- `title?`：`{text, cue}`。
- `parts`：两个 `{value, text, cue, em?, peak?}`。value 必须是正数，合计 100。
- 区域宽度按 value/100 计算，百分比与说明分别显示，避免窄区塞长文字。

```json
{"line":0,"template":"allocation","parts":[
  {"value":80,"text":"日常基本盘","cue":"八成"},
  {"value":20,"text":"先锋攻坚","cue":"两成"}
]}
```

diagram / roles / allocation 按 3:4 排版；16:9 下整体平移到画面中部显示。

## 单次强调

- 普通文字和卡片约 0.15 秒淡入，随后静止；不再整组弹跳。数字、hero 标题、结论新说法都不自动强调。
- 所有带 cue 的元素可写 `em: true`，**每场最多一个**，多写会报错。只放大该元素里字号最大的那行字，容器和其他文字不动：默认 1.10 倍、上限 1.12，0.6 秒内归位。
- 引擎会根据邻近文字和平台安全区自动降低倍率；放不下时改为一次黄色底色高亮。`peak: 1` 直接选高亮而不缩放。

## yazai：芽仔

```json
"yazai": { "face": "surprise", "faceCue": "看傻" }
"yazai": { "face": "loading", "faceCue": "看着它", "hold": 2.5 }
"yazai": { "face": "idea", "faceCue": "不排斥", "action": "approach", "at": "front", "walk": true, "cue": "不排斥" }
```

- `face`：只能是 `surprise`、`happy`、`doubt`、`idea`、`loading` 之一。
- `faceCue`：表情对应的口播原词，表情和这个词同时出现。
- `hold`：表情停留的秒数，默认 1.5，`loading` 可以写 2–2.5。
- 表情只亮面罩，不再有头顶符号、不自动放大、不推镜头；芽仔平时静止，不呼吸、不抖嫩芽。
- `action`：可选，配合表情的一个动作，由 `faceCue` 驱动：`retreat` 短暂收身后退、`approach` 向前走、`celebrate` 一次小幅跃起、`observe` 注视重点、`push` 一次前倾。
  - `approach` 必须同时写 `at: "front"`、`walk: true` 和 `cue`；`walk` 不能叠加其他动作。
  - 现有角色肩部结构不支持单独抬手指向，用整体倾身和内容高亮表达关系。
- `at` + `cue` + `walk`：说到 `cue` 时换到 `at` 站位，写了 `walk: true` 就走过去。只在剧情转折处用，`at` 一般写 `front`。
- 不写 `yazai` 时，芽仔按场景类型自动站位、不出表情。
- 以下写法已停用，写了会报错：`mood`、`moods`，以及上述 5 种以外的表情和动作。
